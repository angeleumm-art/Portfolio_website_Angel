# Logging order inquiries to a spreadsheet

Every order placed on the site opens a pre-filled email in the customer's own
mail app, addressed to `orders@angellesucre.com`. The website itself never sees
that data, so the spreadsheet has to be built from the inbox.

`gmail-orders-to-sheet.gs` is a Google Apps Script that checks Gmail every 15
minutes, reads the cake details out of each order email, and appends **one row
per cake** to a Google Sheet.

## Setup (about 5 minutes, done once)

1. Sign in to Google as the account that **receives** mail for
   `orders@angellesucre.com`.
2. Go to [sheets.new](https://sheets.new) to create a blank spreadsheet and name
   it something like `Angelle Sucre — Order Inquiries`.
3. In that spreadsheet choose **Extensions → Apps Script**.
4. Delete the sample `function myFunction() {}` code, then paste in the entire
   contents of `gmail-orders-to-sheet.gs`.
5. Click the save icon.
6. In the function dropdown at the top, pick **`createTrigger`** and press
   **Run**.
7. Google will ask for permission to read your Gmail and edit the spreadsheet.
   Choose your account, click **Advanced → Go to (project name)**, then
   **Allow**. This is the standard warning for a script you wrote yourself; the
   script only reads mail and writes to your own sheet.

That's it. New inquiries appear automatically from then on.

To pull in orders that arrived *before* setup, run the
**`backfillExistingInquiries`** function the same way.

## What lands in each row

| Column | Where it comes from |
| --- | --- |
| Received | Email timestamp |
| Customer Name / Customer Email | The sender's address |
| Item # / Item | Each `--- Cake 1: Spring Florals ---` block |
| Size / Price | `Cake Size: 6" ($130)`, split into two columns |
| Flavor, Cream, Filling, Nut Allergy, Shape | The matching lines in the email |
| Pickup Date & Time | `Desired pickup date & time:` |
| Additional Notes | `Additional notes:` |
| Instagram / Phone | `Instagram/Phone # (Both Required):` |
| Email Link | Click to open the original email in Gmail |
| Message ID | Used internally to prevent duplicate rows |

An order with three cakes produces three rows sharing the same customer and
pickup time, so the sheet doubles as a production list.

Inquiries that aren't structured cake orders — wedding and event emails sent
from the contact buttons, for example — still get a row, marked
`(unstructured inquiry)` with the full message text in Additional Notes. They
won't be dropped.

## About Excel

This writes to Google Sheets, which is what Apps Script can update live. To get
an actual `.xlsx` file at any time, use **File → Download → Microsoft Excel**.
If you need a spreadsheet that stays in Excel format and updates on its own,
that requires a different setup (Microsoft 365 rather than Google) — worth
knowing before you rely on it.

## Two things that could trip this up

**If `orders@angellesucre.com` is a Google Group** rather than an alias or a
mailbox, the messages may live in the group's archive instead of a personal
inbox, and the script won't find them. Test by searching
`to:orders@angellesucre.com` in Gmail while signed in as the account you used
for setup. If results appear, you're fine. If not, either add yourself as a
group member who receives copies, or change `SEARCH_QUERY` at the top of the
script to match where the mail actually arrives.

**Duplicate protection** works two ways: processed threads get a Gmail label
called `Logged to Sheet`, and every row records its message ID. Don't delete the
Message ID column — it's what stops the same order being logged twice.

## Changing things later

The settings at the top of the script are the only lines meant to be edited:

- `SEARCH_QUERY` — which emails to watch. Any Gmail search works, e.g.
  `to:orders@angellesucre.com OR to:angelle@angellesucre.com`.
- `SHEET_NAME` — which tab to write to.
- `PROCESSED_LABEL` — the Gmail label used to mark finished threads.
- `OWN_DOMAIN` — mail sent from this domain is skipped, so your own replies
  never become rows.

One structural note: the script reads the exact wording the site puts in the
email, which is generated by `buildCartEmailBody` in `src/CartContext.jsx`. If
you later reword those lines — renaming `Cake Flavor`, say — update
`assignItemField_` and `TAIL_LABELS` in the script to match, or those columns
will come through blank.
